# `rex` 使用说明

录电脑上的声音——你自己说的，或者电脑正在放的（播客、视频、网页），或者两个一起。
录完可以一条命令转成文字。**全程本地，不联网**（除了第一次下 whisper 模型）。

代码在 `tools/rex.sh`。安装时把它软链到 `~/.local/bin/rex`（见 README），之后任何目录下都能直接敲。

---

## 一、命令速查

| 命令 | 干什么 |
|---|---|
| `rex` | 录麦克风。**正在录的时候再跑一次就是停**（所以绑一个快捷键就够） |
| `rex sys` | 录系统声音：播客、视频、网页里正在放的任何东西 |
| `rex both` | 麦克风 + 系统声音。一个文件：听的是混音，里面两路各存一条轨 |
| `rex both --split` | 同上，但存成两个文件 |
| `rex stop` | 停。报时长、体积、电平 |
| `rex trim` | 切掉最近一次录音**末尾**的空白（忘了停的那段）。原件进废纸篓 |
| `rex trim 文件 --to 49:30` | 手动指定只保留到哪里 |
| `rex who [文件] [人数]` | **按声纹分人**：手机录的多人谈话、10-11 之前的 `rex both`。已经转写过的不重转 |
| `rex go [文件]` | **一条龙**：转写 → 分人 → Claude 校对（报告改了哪里）→ Claude 分析（能接着聊） |
| `rex auto install` | 盯着 `~/Recordings/收件箱`，**丢进去的录音自动走 `rex go`** |
| `rex auto` / `rex auto open` / `rex auto uninstall` | 看状态 / 在访达里打开收件箱 / 卸掉 |
| `rex login` / `rex login status` | 登录 Claude 账号（校对和分析用它）/ 看登上没有 |
| `rex chat [文件]` | **接着和那条录音的分析会话聊**；不给文件就是最近一条有分析的 |
| `rex app` | **录音台**：本地网页界面，录音、拖文件、逐条确认校对、接着问都在里面（见下面「录音台」） |
| `rex app stop` / `rex app status` / `rex app restart` | 关掉 / 看开着没有 / 重起 |
| `rex text` | 把最近一次录音转写成文字。`rex both` 录的出**对话稿**：谁、几点、说了什么 |
| `rex text 某文件` | 转写指定的音频文件（任何 ffmpeg 认识的格式） |
| `rex phone` | 列出 iPhone 语音备忘录（iCloud 同步过来的） |
| `rex phone 1` | 取第 1 条，拷进 `~/Recordings/` 并转写 |
| `rex in` | 列出 `~/Downloads` / `~/Desktop` 里可转的音视频（AirDrop 落点） |
| `rex in 1` / `rex in all` | 转其中一个 / 全部。**只拷贝，绝不动原件** |
| `rex url 链接` | 下播客单集音频（小宇宙等）并转写 |
| `rex check` | 用麦克风录 3 秒扔掉，只看有没有真的收到信号（第一次会弹麦克风授权框，点允许） |
| `rex check sys` | 放一声测试音，用系统音频接口录；收到了就把它设成录电脑声音的默认（第一次弹「仅系统录音」授权框，点允许；见下面「戴 AirPods 录电脑声音」） |
| `rex status` | 在录吗？录了多久？ffmpeg 还在动吗？ |
| `rex ls` | 最近十次录音，带时长和体积 |
| `rex find 词` | 在转写稿**和登记过的文档**里找；不给词就列出全部稿子 |
| `rex open` | 在访达里打开录音文件夹 |
| `rex devices` | 有哪些麦克风和输出设备，现在默认用哪个 |
| `rex help` | 帮助 |
| `rex mic` | 明确只录麦克风（无参数的 `rex` 就是它的开关；选项直接跟在后面也行：`rex --device "AirPods Pro"`、`rex --wav`） |
| 别名 | `rex s`=stop、`rex t`=text、`rex st`=status、`rex f`=find、`rex dev`=devices、`rex all`=both、`rex system`=sys、`rex iphone`=phone、`rex drop`=in、`rex dl`=url、`rex cut`=trim、`rex speakers`=who |

参数：

| 参数 | 用在哪 | 说明 |
|---|---|---|
| `--split` | `both` | 存成两个文件（默认的单个文件里已经分轨了，一般用不着） |
| `--wav` | 录制（`rex` / `mic` / `sys` / `both`） | 录成 24bit WAV 而不是 m4a。要拿去做音频分析时用 |
| `--device "名字"` | 录制（`rex` / `mic` / `both`） | 指定麦克风，名字从 `rex devices` 里抄 |
| `--lang zh\|en\|auto` | `text` | 转写语言，默认 `auto`（会自动探测并分段，见第五节） |
| `--no-vad` | `text` | 关掉人声检测（默认开着） |
| `--no-rename` | `text` / `phone` / `in` / `url` / `go` | 转写完不按关键词改名，保持时间戳名字 |
| `--names 我,老师` | `text` | 对话稿里两边叫什么，前一个是麦克风那边。默认「我,对方」 |
| `--who [人数]` | `text` / `phone` / `in` / `url`（`go` 默认就带） | 转写完顺手按声纹分人（同 `rex who`） |
| `--to 49:30` | `trim` | 只保留到这个时间（也认 `1:02:03` 和秒数） |
| `--dry-run` | `trim` | 只报告会切多少，不动文件 |

## 二、三种模式，分别什么时候用

### `rex` —— 只录你自己

想到什么随口说，事后转成文字当素材。最常用。

用**你在系统里选的那个输入设备**——戴着耳机、系统输入是耳机，它就用耳机的麦克风，
不用改任何设置。

> ⚠️ 用蓝牙耳机麦克风时它会提示一句：耳机会掉进免提模式（采样率 48k → 24k），
> 播放音质当场变糊。只录自己说话无所谓；如果你同时在听东西，加
> `--device "MacBook Air Microphone"` 换成内建麦克风。

### `rex sys` —— 只录电脑在放的

播客、视频、网课、网页里的音频，任何从扬声器出来的东西。

**耳机照常能听见**，见下面第八节。

### `rex both` —— 两个一起

打电话、开线上会、上网课、边看边评论。录出来**一个文件**，播放器里听到的是混音，
文件里另外存着两条原始轨：

| 轨 | 里面是什么 | 干什么用 |
|---|---|---|
| 0 号 | 混音 | 播放器默认只放这条（另外两条是 disabled，QuickTime 不会叠着放） |
| 1 号 | 只有麦克风（你） | 转写 |
| 2 号 | 只有系统声音（对方 / 电脑在放的） | 转写 |

**转写时这个区别很值钱**——`rex text` 两轨各转各的，合成一份对话稿，谁说的
一目了然（第五节「谁在说话」）。

`--split` 还能用，存成两个文件：

```
2026-08-16_143052_both-mic.m4a    ← 只有你的声音
2026-08-16_143052_both-sys.m4a    ← 只有电脑的声音
```

默认那个文件里已经分轨了，一般用不着它。`rex text` 碰到这样的一对，也合成一份对话稿。

> **2026-10-11 之前录的 `both` 是真混成一轨的，分不开了。**当时文档建议开会用
> `--split`：混音是直接相加（`normalize=0`），两边电平差很多时自己的声音被埋——
> 2026-08-19 一场会实测麦克风峰值 −45.3 dB、系统声音 −13.0 dB，**差 32 dB（约 40 倍）**，
> 16 分钟只转出 24 行；事后用 `loudnorm` / `dynaudnorm` 补救都不行，**混完再补救是
> 补不回来的**。现在转写不用混音那条了，这个问题跟着没了。

### 开会（腾讯会议 / Zoom）：会议 App 会抢走麦克风

**对方的声音基本录得到**（走系统输出 → BlackHole，或系统音频接口。走 BlackHole 时可能被 AirPods 自动切换
抢走，见第九节「戴 AirPods 录电脑声音」）。**你自己的声音不一定。**

真事，2026-08-16：`rex both --split` 录了一场 128 分钟的腾讯会议。麦克风那轨
第 1 分钟峰值 −3.9 dB（正常说话），**第 2 分钟开始就是 −91.0 dB**，之后 126 分钟
全是数字静音。128 分钟的会，自己那边只留下开头 173 个字的「哈喽哈喽，能听见吗」。

为什么：会议 App 用 macOS 的 Voice-Processing I/O 做回声消除，它会把输入设备
拉进一个特殊模式，**把别的读取方踢掉**。

> 之前这份文档写过「两个进程可以同时开同一个麦克风，所以没问题」。
> 那个结论来自两个 ffmpeg 同读一个设备的实测——测是真测了，但**测的不是真实场景**。
> 会议 App 走的是另一条路径，实际会踢人。已更正。

**办法是让两边用不同的麦克风。**跑 `rex devices` 看有哪些，然后：

- 会议 App 的麦克风设成**耳机**（或 iPhone 麦克风）
- `rex both --device "MacBook Air Microphone"`

两边不碰同一个设备就不冲突。反过来也行——关键是错开。`rex stop` 的分轨检查会报
麦克风那一轨有多少是数字静音，被抢了当场就能看出来。

**还有反方向的一条：录到一半戴上蓝牙耳机，系统输出被改走、绕过 BlackHole**，对方那一路从那一刻
起是数字静音。2026-09-26 一场通话就这样丢了对方几乎全部的话；当时停了重开，戴着耳机开录，几秒后
又断了。现在走 BlackHole 时每两秒查一次输出、被切走两秒内接回；换成系统音频接口（`rex check sys`）
则根本不受影响。看门狗、`rex stop`、`rex text` 也都会报对方那一轨的情况，不会悄悄丢。见第九节。

顺带一提：会议里用蓝牙耳机时，耳机本来就已经掉进 HFP 免提模式了（会议 App 在用
它的麦克风），所以「别用蓝牙麦克风免得拖糊播放」那条顾虑在通话场景下不成立。

### 看门狗：断了要当场知道

上面那次事故真正的代价不是「录失败」，是**录了两小时才发现失败**。所以现在录制期间
每 3 分钟自查一次，每一路都看采集程序半秒写一次的电平文件：十秒没有新帧 = 采集停了，帧数不涨 = 卡住，
麦克风数字零超过 3 秒 = 没信号；系统声音走 BlackHole 时另查输出路由。断了就弹通知。走 BlackHole 时
另有每两秒一次的路由监视，输出被切走两秒内接回。录音要是自己停了（到了时长上限、设备断开、磁盘满），
看门狗会替你收尾——切回输出、写完文件、弹一条带声音的通知——不会让直通设备一直占着输出。
`rex stop` 会把这些记录摆出来：

```
录制期间的路由和看门狗记录：
  23:13:49  输出被切到「AirPods Pro」，已经重新接上，系统声音接着录
  23:40:02  麦克风断了（峰值 -91.0 dB），从现在起录的是数字静音
```

只在「由通到断」那一刻报一次，不会每三分钟刷屏。`REX_WATCH=秒数` 改间隔，
`REX_WATCH=0` 关掉。

> ⚠️ **系统声音这一路曾经会误报，2026-08-19 修了。**原来两路共用「峰值 < −70 dB
> 就是断了」的判据。对麦克风成立——真麦克风再安静也有本底噪声，安静房间实测
> −68 dB 上下。**对 BlackHole 不成立**：虚拟设备上没有信号就是真正的数字零，
> 实测什么都不放时 `max_volume: -91.0 dB`，和「断了」一模一样。
>
> 结果是一场 16 分钟的会里，对方每停下来喘口气就报一次「断了」，中间还报
> 「又恢复了」——而链路一秒都没断过（事后逐 30 秒量文件，全程峰值 −2.6 ~ −19.7 dB，
> 没有任何数字静音）。**「又恢复了」本身就是误报的标志：断掉的音频路由不会自己好。**
>
> 现在系统声音改成查**路由**——当前输出设备里还有没有 BlackHole。耳机断连、
> 别的 app 把输出抢走，这些才是真会断的东西，而且查得准、没有假阳性。
> 报警文案也换成能直接动手的：`当前输出「AirPods Pro」里没有 BlackHole`。

**通知故意不带提示音**——正在录系统声音的话，提示音会被录进去。

会中也可以自己查一次：

```bash
rex status
```

```
● 在录 · both · 已 42 分 10 秒

  ✓ 麦克风（你）：峰值 -48.8 dB
  ✓ 系统声音（对方）：峰值 -14.1 dB
```

麦克风数字零超过 3 秒会标 `✗ 没信号`，某一路 10 秒没新数据标 `✗ 采集停了`，系统声音那路此刻没东西放
是 `○ 此刻没声音`。电平是采集程序每半秒写出来的实时值（`~/Recordings/.cap/*.level`，录音台顶栏的电平条
读的也是它），不是读那个正在写的文件——录制中的 m4a 索引写在末尾，没收尾之前根本打不开；文件大小
也不行，ffmpeg 大块缓冲，实测录了 13 秒两轨都有声音、中途看文件却一直停在 4K。

录有其他人参与的会议，开始前说一声比较稳妥。

### 忘了停：`rex trim`

```bash
rex trim            # 最近一次录音
rex trim --dry-run  # 先看会切多少
```

```
2026-09-22_123128_sys.m4a  （1:43:46）
  末尾空白：49:52 → 1:43:46，共 53:54（峰值 -91.0 dB）
  切到 49:55（多留 3 秒，免得切掉最后一个字的尾音）
  ✓ 1:43:46 → 49:55 · 30.3M → 28.5M
  原件已放进废纸篓（访达里右键「放回原处」可以恢复）
```

**只切末尾，不切中间。**同一条录音里还有 4 段 20~67 秒的停顿（播客里的间歇），
「把所有空白都删掉」会把它们一起切了，后面的时间轴整体前移，已经转写的 `.srt`
就对不上音频了。只切末尾的话，末尾之前每一秒都原样保留，时间戳一个都不动。
开头的空白也**故意不切**，理由相同。

几个细节：

- **判据按音源分**：`sys` 走 BlackHole，静音是 −91 dB 的真数字零，阈值 −70 dB；
  麦克风有本底噪声（安静房间 −55 ~ −70 dB），阈值 −50 dB。共用一个阈值就是
  看门狗那次的坑（见上面「看门狗」那节）
- 只认**至少 30 秒、一直延续到文件结尾**的静音。说话随时会打断它，所以中间的
  停顿再长也不会被当成末尾空白
- **不重新编码**，只截断容器（`-c copy`），音质零损失、几秒钟完成。实测留下的
  49:50 解码后和原件逐字节一致
- 已经转写过的话，`.srt` 里切点之后的条目会一并去掉，`.txt` 按剩下的重建
- `--split` 录的那一对会**一起切**
- 空白不一定是静音——电脑在放别的、风扇声很大，它就不会动。这时候用
  `--to 49:30` 手动指定。它会把要丢掉那段的峰值打出来，是真内容一眼就看得出

> **原件进废纸篓，不删。**这个工具链在这台机器上删过作者的录音（`rm` 不经过
> 废纸篓），所以这里绝不删除：新文件验过时长，才用 macOS 自带的 `trash` 把原件
> 送走，访达里「放回原处」就能恢复。

顺带一提：54 分钟数字静音只占 1.8 MB（AAC 压静音压得极狠），所以切它省的不是
空间，是**时长**——转写、找语言、`rex ls` 里看到的数字都对了。

**下次停的时候会自己提醒。**`rex stop` 现在会看最后 5 分钟，一直没声音就说：

```
    ⚠ 最后 5 分钟一直没声音（峰值 -91.0 dB），多半是忘了停。
      rex trim 切掉末尾空白（中间的停顿不动，原件进废纸篓）
```

## 三、文件在哪

一律落在 `~/Recordings/`。命名是 `日期_时间_模式`：

```
2026-08-16_143052_mic.m4a
2026-08-16_143052_sys.m4a
2026-08-16_143052_both.m4a
2026-08-16_143052_both-mic.m4a  +  ..._both-sys.m4a     （--split）
```

转写结果就放在旁边，同名的 `.txt` 和 `.srt`（带时间轴）。`rex both` 录的是对话稿，
每一轮前面写着是谁。

体积（每小时）：

| | 格式 | 一小时大概 |
|---|---|---|
| `rex` | AAC 单声道 96 kbps | 43 MB |
| `rex sys` | AAC 立体声 160 kbps | 72 MB |
| `rex both` | 混音 160 kbps + 两条分轨各 64 kbps | 130 MB |
| `--wav`（立体声） | 24bit / 48kHz PCM | **1.0 GB** |

**有个 6 小时的保险丝**，到点自己停，防止忘了停把盘写满。要录更长：

```bash
REX_MAX=36000 rex sys
```

## 四、找回以前的稿子

自动起名之后文件名会变，**按记忆里的旧路径去翻必然扑空**。所以别记路径，用搜：

```bash
rex find docker
```

```
  08-14   2831 字  2026-08-14_1609_phone_Projection-GUI-Session.txt
     走Docker了
     不用那个Docker的形式
     那个是用Docker做的

  录音稿：1/6 份命中 · ~/Recordings
```

文件名和正文一起搜。不给词就列出全部稿子：

```bash
rex find
```

三点：

- 列表里的日期从**文件名**取，不是文件修改时间。重转写一次 mtime 就变成今天，
  一份 08-14 的录音会显示成 08-16——比不显示还糟
- 末尾会提示 iPhone 里还有多少条备忘录**没转写**。「找不到」经常不是丢了，
  是那条压根还没转过
- 搜的不只是录音稿，见下

### 它还会搜文档

`rex find` 除了 `~/Recordings`，还会搜 `~/.config/rex/text-dirs` 里登记的目录。
比如作者登记了一批文档抽出来的纯文本（1099 份、3190 万字）：

```bash
rex find 巴赫金
```

```
  录音稿：0/6 份命中 · ~/Recordings

  文档   309440 字  二十世纪西方文学理论.txt
     巴赫金 ( MikhailBakhtin)。 他 …
     …式主义的最中肯的批评。这一批评的大部分也出自巴赫金之手。巴赫
     （这份里还有 13 处）

  文档   371522 字  巴赫金全集 第3卷.txt

  文档：2/1099 份命中 · /Volumes/Untitled/文档文本
```

三千多万字搜一遍约 1.5 秒。**不给词时文档不会逐条列出来**——一千多行刷屏，
而且它们没有时间线可言，只报个数；要清单去那个目录里的 `_索引.tsv`。

要加别的目录（论文库、笔记导出），把路径写进 `~/.config/rex/text-dirs`，
一行一个，删掉那行就不搜了。

> ⚠️ **硬盘没插会明说。**登记过但当前不可达的目录会打一行警告
> 「这次搜索**没有**覆盖它」。静默少搜一个目录，结果就是「没找到」，
> 而其实是根本没去找——这两件事必须能分清。

稿子全部在 `~/Recordings/`，`rex open` 直接在访达里打开。

## 五、转写

```bash
rex text
```

不给参数就转最近一次录音（`rex both` 录的出对话稿，`--split` 那一对合成一份）。也可以直接给文件，
不限于自己录的：

```bash
rex text ~/Downloads/某期播客.mp3
```

用的是 whisper.cpp + `large-v3-turbo` 量化模型，走 Metal（GPU）。
**实测约 8 倍速**：5 分钟音频 37.9 秒，一小时播客七八分钟。

第一次跑会自动下两个模型，落在 `~/.cache/whisper/`：

- `ggml-large-v3-turbo-q5_0.bin`（547 MB）识别
- `ggml-silero-v5.1.2.bin`（864 KB）人声检测

### 谁在说话：对话稿

`rex both` 录的文件，`rex text` 出来是这样的：

```
[00:01] 我：老师好，能听见吗？

[00:04] 对方：能听见？你那边好了吗？好，我们开始吧。

[00:09] 我：好的，今天想聊一下下学期选课的事，我最近一直在纠结统计那门。
```

**不是猜的，是分轨分出来的。**麦克风那一路只有你，系统声音那一路只有电脑放出来的
（通话对方、网课），录的那一刻就分开了。两轨各转各的，按时间合起来，标签就是对的。

名字可以改，前一个是麦克风那边：

```bash
rex text --names 我,老师
REX_NAMES=我,老师 rex text        # 或者设成默认
```

`.srt` 里每条前面也带着名字。起名用的关键词会跳过这些名字，不会每份都叫「老师」。

**这条路分不开的三种**，交给下面的 `rex who`（声纹）：

- 同一轨里的多个人：线上会议对面三个人都在系统声音那一轨，一律叫「对方」
- 一个麦克风录的多人谈话：手机录音、线下开会
- 2026-10-11 之前录的 `both`：那时是真混成一轨的

转写时可能打印的几行：

| 打印 | 意思 |
|---|---|
| `拆开 N 处` | whisper 把隔着对方一句话的两句并成了一段，按声音切开了（见下） |
| `去掉 N 段回声` | 外放时对方的声音漏进麦克风、又被当成「我」转了一遍，扔掉了。**戴耳机时应该是 0** |
| `⚠ 对方那一轨 N% 是数字静音` | 要么对方一直没出声，要么系统声音中途断了（多半是录到一半戴上了蓝牙耳机） |
| `⚠ 我那一轨 N% 是数字静音` | 真麦克风不会这样：笔记本合着盖，或者会议 App 把麦克风抢走了 |

**「拆开」是怎么回事。**whisper 开着人声检测时，先剪掉静音再识别。单看你这一轨，
对方说话那几秒正好是静音、被剪掉了，于是 whisper 以为你是连着说的，把隔着对方一整句
的两句并成一段——按时间一排，顺序就乱了。合并前会用每一轨自己的音量把段重新定位，
在对方说话的地方切开。切点按时长比例估，偶尔有一两个字落进相邻那一轮。

**去回声为什么这么谨慎。**只看文字：两个人同时说「对对对」会被当成回声；只看音量：
你小声嘀咕一句会被扔掉。所以要文字像、音量轻、**而且时间上真的同时**才算。最后这条
是测试里撞出来的：对方问「是不是担心跟不上」，你答「对，是担心跟不上」——文字
几乎一样，第一版就把这句当回声扔了。复述发生在对方说完之后，回声和原声是同时的。

### 一路声音里好几个人：`rex who`（声纹）

```bash
rex who                      # 最近一条
rex who 某录音.m4a           # 指定文件；已经转写过的不重转，46 分钟的录音约一分半
rex who 某录音.m4a 3         # 知道是 3 个人
rex text --who 某录音.m4a    # 转写和分人一起做
rex phone 1 --who            # 手机录音取出来就分
```

出来是这样的（2026-10-11 一段 2 小时 30 分钟的两人聊天）：

```
[10:18] 说话人2：对我刚想问的是什么方向的research呢，怎么，那些想做什么

[10:22] 说话人1：我想做后训练方面的research，比如说，怎么让它……

[11:35] 说话人2：你会感兴趣的也是，AI Infra或者是做模型的这种，底层研发的公司吗
```

**这是猜的，不是分轨那种确定的标签。**每一小段算一个声纹，按「声音像不像」聚成几堆。
用的是 sherpa-onnx（开源，全程本地，不联网），第一次用时自动下载约 50 MB，解压后
占 93 MB，在 `~/.cache/sherpa-onnx/`，不进仓库。

**怎么数出几个人：先分细，再合并。**先故意把录音分成几十上百小堆（宁可把一个人切成
好几堆，也不让两个人进同一堆），每一堆取十来段算声纹、求**平均声纹**，再把平均声纹
足够像的堆并起来，并到最像的两堆也不够像为止。剩下太小的碎堆（笑声、两人同时说话、
杂音）并给声音最像的那个人。

为什么要平均：两三个小时里同一个人的嗓音会变——累了、激动、离手机忽远忽近，单拿两小段
比，同一个人前后可以比两个不同的人还不像。几十段平均下来，这些一时的变化就抵消了：
同一个人被拆开的两堆平均声纹相似度在 0.8~0.98，两个不同的人在 0.15~0.7。

> 第一版不是这样做的，它直接按单段之间的距离数人数：一段 2 小时 30 分钟的两人聊天被
> 分成了 **12 个人**，04:32 那条两人谈话分成了 4 个人（我当时还照内容说「至少 3 人」，
> 也是错的）。改成现在的办法后，手上四条录音（两场谈话、一段长聊天、一个测试用的合成
> 电话）全部分对，都是 2 个人。

**准不准**：拿 2026-10-10 那场谈话量的——那场两边频谱不一样（通话那头 7.5 kHz 以上
被砍掉），能当参照答案。按句子比，**97% 一致**；剩下 3% 挑出来读，多半是参照答案错了
（对方说的话被频谱规则判成了本机），不是声纹错了。

**多久**（实测）：15 分钟的录音约 40 秒，46 分钟约一分半，2 个半小时约 5 分钟——转写
同一条要二十分钟，分人不是瓶颈。

**人数还是可能错**，尤其是两个人嗓音非常像的时候（测试用的两个合成语音，平均声纹相似度
就有 0.62）。你知道人数时就告诉它：`rex who 文件 2`——它会一直合并到正好剩 2 个人，
不用重新转写，可以反复改。

**名字是「说话人1、2、3……」**，按出场顺序编。谁是谁要你自己对：声纹只知道
「这几段是同一个人」，不知道这个人是谁。

**10-11 之前的 `rex both`（混成一轨）会多做一步**：分完人再按频谱把「本机麦克风这边」
对成「我」、「通话那头」对成「对方」。同一边被拆成两堆时两堆都会对成「我」，人数问题
顺带解决。对不上（比如通话音频本身是全频带的）就保持说话人编号，并且说出来。

只有一个人在说话的录音（讲座、播客、独白）不会被贴上「说话人1」，稿子保持原样。

### 录音台：`rex app`（不用敲命令）

```bash
rex app
```

打开一个只在本机运行的网页（`http://127.0.0.1:8790`）。Safari 里「文件 → 添加到程序坞」，以后从程序坞
点开就像一个 App。

- **录音**：顶上三个按钮——**我 + 对方**（通话、开会：你的麦克风 + 电脑声音，两边各存一条轨）、
  只录电脑声音（网课、视频，**不录你的麦克风**）、只录我（当面聊）。打电话、开会一律按「我 + 对方」。
  录着的时候顶栏显示时长、每一路一根实时电平条和「停止」：你的麦克风没信号、或者哪一路采集停了，
  当场标红；电脑这会儿没放声音显示灰色「没声音」。开录要几秒，这期间连点不会开出第二条
- **加文件**：把音频文件拖进窗口，等于放进收件箱，自动转写 → 分人 → 校对 → 分析
- **手机里的录音**：左下展开，列出语音备忘录（带地点名），点「导入」就取出来处理
- **看一条**：稿子按说话人分颜色，点时间从那里播放；自动改过的词绿底（鼠标停上去看原文），待确认的黄底
- **逐条确认校对**：「校对」页里，Claude 拿不准的每一条都有「采纳 / 不采纳」，键盘 `Y` 采纳、`N` 不采纳、
  `J` / `K` 下一条 / 上一条、空格听这一句；改了的可以「撤销」。改的就是稿子文件本身，报告跟着更新
- **分析**：渲染好的分析报告，里面的时间能点
- **接着问**：直接在页面里问那个分析会话（走你的 Claude 登录，不受终端里别家接口设置的影响）
- **搜索**：搜所有稿子，结果准到哪一句，点时间直接跳过去
- **补做**：没转写、没校对、有几段没校成的，右上角有按钮补
- **删掉一条**：双击左边列表里的一条（或者点详情右上角「删除」），确认后整条录音——音频、稿子、校对、分析——
  移到废纸篓，访达里右键「放回原处」能恢复。正在录的、正在处理的不让删。空录了的直接这样清掉

几点说明：

- 从终端里跑 `rex app` 起它（关了终端它也接着跑）。录音的权限（麦克风、系统声音）记在录音程序
  「rex 录音采集」自己头上，从哪起都一样；只有读 iPhone 语音备忘录目录要的「完整磁盘访问权限」
  还是按终端给的，所以从那个有权限的终端起
- 关掉 `rex app stop`，看状态 `rex app status`，日志在 `~/Library/Logs/rex-app.log`
- 只开在本机，别的电脑连不上；浏览器里别的网页也调不动它（有口令、核对来源）

### 一条龙：`rex go` 和收件箱

**把录音丢进 `~/Recordings/收件箱`，剩下的全自动。**（第一次先装一下：`rex auto install`。
在访达里打开它：`rex auto open`，顺手把这个文件夹拖到访达边栏，以后直接往里拖。）

**什么放进收件箱**：从别处来的音频文件——微信、下载、别人发的、手机导出的——把**文件本身**
（访达里那个图标）拖进去。用 `rex` 在这台 Mac 上录的本来就在 `~/Recordings` 里，不用进收件箱，
直接 `rex go`。拖进去的不是音视频（比如拖成了一段文字，访达会把它存成 `.textClipping`），
会挪进 `收件箱/转不了`，并弹通知告诉你是怎么回事。

丢进去的每一条依次走：

1. **转写**（whisper，本地）
2. **分人**（`rex both` 的分轨 / 声纹，本地；只有一个人就不分）
3. **Claude 校对**：只改语音识别错误——同音字、术语、人名听错。Claude 交回的是一张
   **修改清单**，由脚本在原文里逐字找到再替换；拿不准的**不改**，留给你确认
4. **Claude 分析**：概括、话题、原话摘录、可以追问的地方、决定和待办

结果都在 `~/Recordings`，名字跟着录音走：

| 文件 | 是什么 |
|---|---|
| `….txt` / `….srt` | 校对后的稿子（对话稿带说话人） |
| `….whisper.srt` | 校对前 whisper 的原稿，对照用 |
| `….校对.json` | 校对结果的原始记录（`.校对.md` 由它生成）。有几段没校成时记着行号，再 `rex go` 只补那几段 |
| `….校对.md` | **改了哪里**（时间、原文 → 改成、理由），以及「拿不准、没改的，请你确认」 |
| `….分析.md` | 分析报告。开头写着 `rex chat "…"`，**跑它回到那个会话接着问** |
| `….对话.json` | 录音台「接着问」的问答记录和用的会话号（重做分析后自动换成新报告的会话） |

一收到会先弹一条「开始处理（N 分钟）」，做完再弹一条（「校对改了 N 处，M 处待你确认」）。
处理完原件挪进 `收件箱/已处理`，不删。稿子短得离谱（几十分钟的录音只转出几个字）时不交给 Claude，
弹通知「转写可能失败」——那是转写出了问题，校对救不回来。
取不出音频的（不是录音、文件坏了）挪进 `收件箱/转不了`，也弹通知。

不想丢文件夹也行，直接：

```bash
rex go 某录音.m4a
```

不给文件就是最近一条。转写过的不重转、分过人的不重分、校对过的不重校、分析过的不重做，
只补缺的那几步——同一条录音再丢进来一次，不会把第一次的校对报告盖掉。要重做哪一步，
删掉那一步的产物（比如 `….分析.md`）再 `rex go`。

**第一次要做的一件事：登录 Claude。**校对和分析调的是本机的 `claude` 命令行，它要用你的 Claude
账号单独登录一次（桌面 App 的登录它用不上）：

```bash
rex login
```

浏览器里确认就好，只要一次。**如果你的 `~/.zshrc` 把终端里的 `claude` 指到了别家接口**（`ANTHROPIC_BASE_URL`
那几行），别用「跑 claude 再 /login」：带着那些设置是登不了 Claude 账号的，`rex login` 会先清掉它们。
流水线调 Claude 时也一样清掉，所以你平时敲 `claude` 照旧走那一家，流水线走 Claude，互不影响。
查登录状态：`rex login status`。接着聊用 `rex chat`，**别直接 `claude --resume`**——那样会带着
别家接口的设置回到会话，稿子就发到那边去了。

**用量**：校对和分析用的是你 Max 订阅的额度，不按 token 另外收钱；每次用了多少写在报告开头（几次调用、
多少 token、折合 API 价——这个价只是把用量换算成钱，方便比较）。2026-10-12 拿同样 20 行稿子实测：

| 怎么调 | 用时 | 折合 API 价 | 校对结果 |
|---|---|---|---|
| 第一版（从作者的仓库目录起，带上 87 KB 的 CLAUDE.md、默认系统提示） | 128 秒 | $1.28 | 9 条 |
| 空目录 + 自定系统提示，Fable 默认强度 | 81 秒 | $0.31 | 11 条，多数拿不准 |
| 同上，Sonnet | 110 秒 | $0.14 | 把「真本」猜成「真北」、「背头」猜成「版图」 |
| **同上，Fable 低强度（现在用的）** | **24 秒** | **$0.09** | 「真本→真格」「背头→被投」，有把握且对 |

没登录、余额不足、到了用量上限时，转写和分人照做，校对和分析跳过，通知里写明原因；之后对那一条
再 `rex go` 一次（终端里会打出完整的命令），补上这两步。

**改分析要什么**：默认的分析提示词在 `tools/analyze.py` 里。想换（比如访谈录音想看别的）：
写一个 `~/.config/rex/analysis-prompt.md`，有它就用它。

**隐私**：转写、分人全在本地；**校对和分析会把整份稿子发给 Claude**（走你自己的 Claude 登录，
和在 Claude 里粘贴一样）。只有 `rex go` 和收件箱走这两步，`rex text` / `rex who` 不会。

**看它在干什么**：`rex auto` 看状态和日志最后几行；完整日志在
`~/Library/Logs/rex-inbox.log`。

> 为什么收件箱放在 `~/Recordings` 底下，而不是「下载」或 iCloud 云盘：后台自动运行的程序
> 读不了 macOS 隐私保护的文件夹（下载、桌面、文稿、iCloud 云盘）。连这个仓库在「文稿」里，
> 后台都读不了它的脚本——所以 `rex auto install` 往 `~/.local/share/rex-runtime`
> 拷了一份脚本给后台用，你平时在终端里跑 `rex` 时会自动保持同步。

### 一段录音里换了语言：自动分段

**whisper 只在文件开头认一次语言，之后整个文件按那一种解码。**所以「前半英文、
后半中文」这种录音，直接喂给它会出大事。

2026-08-18 真事，一条 5 分 39 秒的会议录音，前 42 秒英文、之后 4 分 57 秒中文
（占 82%）。它在 t=0 判定 `en`（置信度 0.99），然后：

```
[00:01:20]   It's better than the other bits format.
[00:01:21]   It's better than the other bits format.
…（同一行连着 167 遍，一直到录音结束）
```

**中文一个字都没出来，而且它不报错。**自动命名还老老实实照着这句话给文件起了名，
叫 `2026-08-18_1324_phone_It's-better-format`——一个静默的失败，被下游包装成了
一个看起来正常的结果。

现在 `rex text` 默认会**先探语言再分段转**：

```
  探测 13 点（网格 31s，二分 2 次）
  语言分段：en 00:00–00:42 · zh 00:42–05:39
  分 2 段各按自己的语言转写

  ── 第 1/2 段 · en · 00:00–00:42 ──
  ── 第 2/2 段 · zh · 00:42–05:39 ──
  2 段合并完成（时间轴已按各段起点校正）
```

同一条录音重转，中文 0 字 → **1171 字**，最长「连续相同行」167 → 4。

三个实现上的取舍，都是实测定的：

- **探测有成本。**一次约 1.5 秒，几乎全花在加载 547 MB 模型上，不是识别本身。
  所以先铺粗网格（最多 40 点），只有相邻两点语言不同才去二分找边界。
  网格既有上限（40 点）也有**下限密度**（至少 60 秒一格）——只设上限不够，
  21 分钟的文件按 30 秒一格正好顶到 40 点，那是 27% 的开销。实测：
  5 分钟约 20~30%、21 分钟约 20%、130 分钟约 6%。**短文件的比例下不去**，
  因为探测次数有个底（要覆盖开头和结尾），而转写时间跟着时长缩
- **探测点按窗口中心记，不按起点记。**从 31 秒开始的 30 秒窗口被判成中文，
  意思是「31~61 秒里中文占多数」，不是「31 秒处是中文」。照起点记会把边界
  系统性地往前推半个窗口——实测真边界 42 秒，按起点记报 30 秒，
  12 秒的英文被划进中文段
- **粗查用 30 秒窗口，二分改用 10 秒窗口。**宽窗口跨在边界上时两种语言各占一半，
  精度就卡死在 30 秒；换 10 秒窗口直接指到 42 秒，置信度反而更高
  （en 0.98 / zh 0.91）

**只认中文和英文**（白名单，改 `REX_LANGS=zh,en,ja` 可以加）。白名单外的判定当作
「不确定」处理、并进邻居段，并且会打印挡掉了什么。起因见第九节：卡顿的音频让语言
识别把 5.8 分钟判成冰岛语，按冰岛语硬解，一个字都没出来。

**太安静的地方不认语言。**whisper 对着房间底噪会很自信地说「这是英文」（实测置信度
0.78）。2026-09-26 一条录音里几段几乎没人说话的地方就这样被判成英文、按英文硬解，
零星几句中文被翻成了英文。现在每个探测窗口先量一下有多少是真有声音的，不到两成就
不认语言、跟着前后段走，会打印「其中 N 点太安静」。整条都太安静（比如对方几乎不出声
的那一轨）时，按 `REX_LANGS` 的第一个（默认中文）转。

单语录音探到只有一种语言时，会**显式指定**那一种再转，不再让 whisper 自己猜。
已经知道是什么语言的话可以直接跳过探测：

```bash
rex text --lang zh 某文件.m4a
```

### 重复陷阱：`-mc 0`

上面那个 167 遍不只是语言选错的锅。whisper 默认把已经转出来的文本当上下文喂回去
（`--max-context -1`，无限）——**一旦开始重复，重复本身进了上下文，于是更倾向
重复**，正反馈。实测同一个文件、同样按英文硬解：

| | 最高频那一行重复 |
|---|---|
| `-mc` 默认（无限上下文） | 54 次 |
| `-mc 0` | 4 次 |

现在一律带 `-mc 0`。代价是跨句连贯性略降（它不再知道前文说过什么），
对口述稿这笔买卖划算——连贯性丢一点可以接受，整段变成同一句话不行。

命名那一层也独立防了一道：同一句话在稿子里最多算两遍，多的不计入词频。
**不要让一句话重复几百遍这件事，决定整份稿子叫什么。**

### 认错词怎么办：两层

**第一层 `tools/whisper-prompt.txt`** —— 提示词表，转写前喂给模型。实测有效：

| | 结果 |
|---|---|
| 不给词表 | 往文 / 赤心寻天 / 双文 / 新国变 / 哲理变 |
| 给了词表 | 网文 ✓ 赤心巡天 ✓ 爽文 ✓ 新国辩 ✓ 哲理辩 ✓ |

**这份文件要短。**长度上限约 224 token（中文一个字 1~2 个），超了会被截断，
反而更差——实测更长的词表结果比短的还烂。只放**真的被听错过**的词。

**第二层 `tools/whisper-fix.txt`** —— 转写完做确定性替换，每行 `错的→对的`。
提示词是偏置、不保证生效（同一个词在两段录音里可能一次对一次错），掰不回来的放这里。

> ⚠️ 中文没有词边界，这是**无条件字符串替换**，会误伤。
> `往文→网文` 会把「通往文学」改成「通网文学」。只放足够独特的错法。
> 每一处替换都会打印出来，看到不对就删掉那一行。

两个文件改完直接生效，不用重编任何东西。

**这两个文件放哪**：仓库里的 `tools/whisper-prompt.txt`、`tools/whisper-fix.txt` 是空模板。拷到
`~/.config/rex/` 下再改——那里的优先，不进仓库，`git pull` 也冲不掉。

### 转写完自动起名

转写完会从稿子里抽三个关键词，把文件改成认得出来的名字：

```
2026-08-14_1609_phone.m4a                             ← 改之前
2026-08-14_1609_phone_Projection-GUI-Session.m4a      ← 改之后
```

音频、`.txt`、`.srt` 三个一起改，前缀还是时间戳，所以按时间排序不受影响。

抽词在 `tools/keywords.py`，**纯词频、不联网**——为了起个文件名把私人录音稿发给
某个 API，是拿「全程本地」这个承诺换便利，不划算。三条规则：

- 首尾是虚词的片段直接排掉（「的问题」「个东西」这种切歪的）
- **`whisper-prompt.txt` 里的词权重乘 5**。那份表本来就是你的领域词汇，
  命中了几乎一定是关键词。实测中文稿不带词表抽出「赤心巡天-网文-**文章**」，
  带词表变成「赤心巡天-网文-**爽文**」
- 中文稿里夹的英文权重更高。技术类的口述稿里，`Docker`、`GUI`、`Session`
  这种词比任何中文双字词都有区分度

**它抽的是「反复提到的词」，不是「这段在讲什么」。**一段一直在说某个词但重点在
别处的稿子，它会起错名字。名字只是索引，不是摘要。不想要就 `--no-rename`。

两条边界：

- **同一份再转一次不会把关键词接第二遍**。判据是「文件名还是不是本工具生成的
  那个格式」，已经起过名的就不再动
- **`rex text` 指过来的外部文件不会被改名**。`~/Downloads` 里的播客是别人的文件，
  只给转写稿起名，原件一个字节都不动

调词表的时候可以直接看候选排序：

```bash
python3 tools/keywords.py 某个稿子.txt --glossary tools/whisper-prompt.txt --verbose
```

### 空轨为什么是空的

whisper 在没人说话的音轨上会**编**内容。实测一条只有环境底噪的轨被转成
「中文字幕:王智英 李宗盛」——训练数据里混了带字幕的视频。

所以默认开 VAD，没人声的段落整段跳过，空稿会明说「这一轨 VAD 没找到人声」。
想看原始行为加 `--no-vad`。

## 六、手机上录的

iPhone 的语音备忘录经 iCloud 同步到 Mac，`rex` 直接接得上——**手机负责按一下就录，
Mac 负责转写**，词表和替换表都复用，不用在手机上再维护一套。

```bash
rex phone      # 列出最近 10 条
rex phone 1    # 取第 1 条，拷进 ~/Recordings/ 并转写
```

```
iPhone 语音备忘录（最近 10 条）

   1  2026-08-15_2121   69 分 39 秒    287M 空间音频
   2  2026-08-14_1609   14 分 07 秒    6.5M
   3  2026-08-14_1440   46 分 20 秒     22M
```

### 手机那头要设的

1. 设置 → 你的名字 → iCloud → **语音备忘录打开**（同步靠它）
2. 设置 → 操作按钮 → 选**语音备忘录**。按住就开始录，松开停
3. 想要第二个入口：控制中心里也可以加语音备忘录

### 它做了什么

取中选那条的**第一条音轨**，转成单声道 AAC 存进 `~/Recordings/`，
然后走和 Mac 录音完全一样的转写流水线。

为什么拷一份而不是直接转原件，三个理由：

- iPhone 17 Pro 的语音备忘录默认录**空间音频**（`.qta`），一小时 287 MB，取完 48 MB
- `.qta` 里有**两条音轨**，其中一条是 ffmpeg 解不了的 `apac`。所以必须显式
  `-map 0:a:0`，不能赌 ffmpeg 的默认选流
- 备忘录容器归 Voice Memos 管，你在手机上删掉那条备忘录，原件就跟着没了

同一条取过一次就不再重取，只重新转写。

### 播客：`rex url`

```bash
rex url https://www.xiaoyuzhoufm.com/episode/670a025626fe2954b1a092f3
```

```
  来源：og:audio
  节目：投资ABC · E33 财富规划：加上这一步，你的投资理财之路才算完整
  时长：21 分 25 秒
  ✓ ~/Recordings/2024-10-14_0000_web_投资ABC-E33-财富规划-加上这一步….m4a  37.6M

转写 … → 6263 字
```

**不需要装任何下载器。**小宇宙这类页面自己就把音频地址摆在 `og:audio` 里——
那是 Open Graph 的标准标签，公开它就是为了让别的播放器能嵌。实测那个
`media.xyzcdn.net/….m4a`：没有鉴权、没有签名、没有防盗链，一条 curl 就下来了。

取地址按可靠性走四道，**四道都没命中就明说找不到并打印试过什么**：

1. 链接本身就是音频文件（`.m4a`/`.mp3`…）——直接下，不解析网页
2. `og:audio` / `twitter:player:stream`——标准标签，最可靠
3. `__NEXT_DATA__` 里的 `enclosure.url`——顺便拿到标题、播客名、发布日期、时长
4. 兜底：整页正则捞音频链接（不一定是正片，会标出来）

文件名用**单集的发布日期**而不是下载日期，否则一堆老节目会挤在今天，
`rex find` 的时间线就废了。名字里已经带了真标题，所以**不再走关键词自动命名**
——那一层是给没有标题的口述稿用的。

> ⚠️ **下不全要报错，不能打 ✓。**这条是踩出来的：第一版拿到 39432614 字节里的
> 1048576（正好 4 个读块）就退出了，然后照样打了个 ✓——`urlopen` 的 `read()`
> 在对端提前关连接时返回空字节串，**不抛异常**。现在会核对 `Content-Length`，
> 差字节就用 `Range` 续传（重试 5 次），仍然差就报错并删掉半截文件。

给公开发布的播客用，和任何播客客户端做的事一样。付费专栏、会员专享的页面里
本来也没有公开的音频地址。

### AirDrop 过来的：`rex in`

不想走 iCloud 同步、直接从手机 AirDrop 到电脑也行。AirDrop 落在 `~/Downloads`，
然后：

```bash
rex in
```

```
可以转的文件（改 REX_DROP 换扫描目录）

   1    69 分     67M  Main St 4.m4a
   2    46 分     23M  Central Library 7.m4a
   5   130 分    125M  Main St 3.m4a

  转一个：rex in 1    转多个：rex in 1 3    全转：rex in all
```

```bash
rex in 1
```

转过的会标「已转过」，`rex in all` 自动跳过它们。扫描目录用 `REX_DROP` 改
（冒号分隔多个）。

**iPhone 按地点给语音备忘录命名**（`Main St 4`、`Central Library 7`），
这个名字有信息，所以保留进文件名而不是换成时间戳：

```
Main St 4.m4a  →  2026-08-15_2339_drop-Main-St-4.m4a
                →  转写后 2026-08-15_2339_drop-Main-St-4_关键词.m4a
```

结尾那个编号会特意留着——同一个地点录了七条，靠它区分。名字太长会按**词**截断，
不从单词中间切。

两件事值得知道：

- **只拷贝，绝不移动、绝不删除原件。**`~/Downloads` 是你的文件夹，这个工具没有
  资格动里面的东西。实测跑完原件字节数不变。
- **能无损搬运就不重编码。**AirDrop 过来的是 AAC，直接搬进 mp4 容器是瞬时的——
  实测一个 130 分钟、125 MB 的文件搬完只要 **0.49 秒**。源不是 AAC（wav / flac /
  opus）时 `-c:a copy` 会失败，那时才退回重编成 AAC。

### 录手机正在放的东西：做不到，只能绕

**iOS 不允许任何 App 抓系统音频**，没有 BlackHole 的等价物，这是沙盒规则，不是缺个工具。

绕法是**屏幕录制**：控制中心 → 录屏，它会连 App 的声音一起录。录完在「照片」里，
AirDrop 到 Mac 或者存进「文件」，然后：

```bash
rex text ~/Downloads/某个录屏.mov
```

`rex text` 认 `.mov`，会自动挑第一条音轨。两个限制先说清楚：

- **有 DRM 保护的内容录不到声音**——画面有、声音是静的
- 录屏会把**通知音**一起录进去

如果只是想要某期播客的文字，更直接的路子是拿到原始音频文件（播客 App 里下载，
或者在 Mac 上从 RSS 直接下），再 `rex text`，比录屏干净。

### 无效字节

真机录音上踩出来的一条：whisper 在中文分段边界上偶尔吐半个字，转写稿里就留下一个
不合法的 UTF-8 字节。合成语音测不出来，一转真实的十几分钟录音就崩——
Python 抛 `UnicodeDecodeError`、`tr` 报 `Illegal byte sequence`，替换那层整个不执行，
而且字数还会算错（当时报 1454 字，实际 2831 字）。

现在会自己修掉并报出来：

```
! 有 1 处无效字节（whisper 在分段边界上吐了半个字），已标成 �
```

不静默丢——让你知道那个位置原本有东西。

## 七、绑成快捷键

`rex` 无参数是**开关**：没在录就开始录麦克风，正在录就停。一个键就够。

1. 打开「快捷指令」App，新建一个
2. 加一个「运行 Shell 脚本」动作，内容写 `export PATH="/opt/homebrew/bin:$PATH"; "$HOME/.local/bin/rex"`
   （快捷指令起的 shell 不读 `~/.zshrc`，不加 PATH 它找不到 ffmpeg）
3. 右侧信息面板里设一个键，比如 ⌥⌘R
4. 第一次按会弹麦克风授权框（「rex 录音采集」想使用麦克风），点允许

**绑好之后跑一次 `rex status` 确认它真的还在录**——后台进程能不能活过快捷指令
那一层，值得亲眼验一次。

## 八、它对你的音频设置做了什么

只有走 BlackHole 的 `rex sys` 和 `rex both` 会动，`rex`（只录麦克风）什么都不动。换成系统音频接口之后
（`rex check sys` 通过）**什么都不动**，音量键也照常用——下面这段只是 BlackHole 老路的说明。

录系统声音必须让声音进 BlackHole（一个虚拟声卡），但直接切过去你自己就听不见了。
所以它按**你此刻正在用的输出设备**现建一个「多输出设备」：

```
录之前   默认输出：AirPods Pro
录制中   默认输出：录音直通（AirPods Pro）
                   成员：BlackHole 2ch + AirPods Pro     ← 耳机照常出声
录之后   默认输出：AirPods Pro                            ← 切回来，临时设备删掉
```

换一副耳机、换成喇叭，它都跟着变，不用改配置。
**如果你当前输出本来就带 BlackHole**（比如你手动选了 Multi-Output Device），
它一个字都不动。

代价只有一条：录制期间**音量键不管用**（多输出设备不支持硬件音量），
用 App 自己的音量条。

## 九、出问题了

### 2026-09-22 之前录的系统声音，都少了 11~21%

**这不是你的操作问题，是工具的 bug，已修。**原来采集交给 ffmpeg 的 avfoundation，
它会静默丢掉约 14% 的采样——不报错、文件正常、能播放，只是均匀地少了一截。

同一时刻对照：CoreAudio 直读 BlackHole 20 秒拿到 **99.94%** 的样本，ffmpeg 只拿到
**85.9%**；麦克风也一样（99.90% 对 86.1%）。设备一个都没少给，是 ffmpeg 丢的。
量本机录音：

| 录音 | 丢失 |
|---|---|
| 2026-08-16 腾讯会议 `both --split`（两轨） | 18.5% |
| 2026-08-20 `sys`（6 小时） | 20.8% |
| 2026-08-28 / 09-18 / 09-22 `sys` | 10.8% ~ 14.1% |
| iPhone 转过来的 `phone` | 0% |

混音的 `both` 看着是 0%，其实一样丢了——它的滤镜链把洞用静音补齐了，所以看不出来。

后果不只是少几句话：声音一卡一卡的，语言识别会乱判（一条录音有 5.8 分钟被判成
冰岛语，一个字没转出来）；转写用的 wav 把空隙挤掉，字幕越往后越对不上音频。

**现在的录音不经过 ffmpeg 采集**，由 `audiocap`（CoreAudio 直读）把每一帧交给
ffmpeg，实测四种模式都是 0 丢失。**以前丢掉的样本找不回来**——采集时就没进文件；
能补救的是时间轴和语言分段，重新 `rex text` 一遍就会用上。

想自己验一条录音丢没丢，**数帧，不要看时长**：

```bash
ffprobe -v error -select_streams a:0 -count_packets \
  -show_entries stream=nb_read_packets,sample_rate:format=duration -of default=nw=1 某.m4a
```

`nb_read_packets × 1024 ÷ sample_rate` 应该约等于 `duration`。


### 录完发现是空的 / 怀疑没录上

先花 3 秒测一下：

```bash
rex check
```

```bash
rex check sys
```

（两条命令第一次跑都会弹授权框——`rex check` 要麦克风，`rex check sys` 要「仅系统录音」——点允许，命令
会等你点完再测。`rex check sys` 自己放一声测试音用系统音频接口录；收不到就再用 BlackHole 那条老路放一次，
两条路都不用你放东西。）

### 戴 AirPods 录电脑声音（2026-10-13）

**AirPods 的「自动切换」会抢输出。**它同时连着 Mac 和 iPhone，Mac 一出声、而戴在耳朵上的 AirPods 没被
用上，它就把输出直接改成 AirPods。录电脑声音原来靠的是「录音直通」（BlackHole + 你的耳机），输出一被
改掉，BlackHole 就收不到了——2026-10-13 那次开录 6 秒后被抢，后面 47 分钟全是静音。

现在有两道防线：

1. **默认：两秒内自动接回。**录音时每两秒查一次输出，被切走就按新的输出设备重新搭直通、切回来，
   记进 `rex stop` 的报告；一分钟里被抢三次以上就不跟它抢了，弹通知（带提示音）告诉你
2. **更稳：系统音频接口。**直接抄电脑放出来的所有声音，**根本不改输出设备**——AirPods 怎么切都不断，
   音量键也照常用。要先授权一次：在终端里跑

   ```bash
   rex check sys
   ```

   会弹「“rex 录音采集”想录制系统音频」：点允许，命令等你点完就放测试音测。看到「✓ 系统音频接口收到了
   测试音」，以后录电脑声音就都走它了。没弹框、或者当时点了拒绝，去 系统设置 → 隐私与安全性 →
   屏幕与系统录音 → 「仅系统录音」里打开「rex 录音采集」，再跑一次。

   **授权记在录音程序自己头上，不是终端。**2026-10-13 第一版是按终端给的：从 Ghostty 跑，系统把请求算在
   Ghostty 头上，而 Ghostty 没申报「录系统声音」这项用途，系统**连框都不弹**，接口静静地交全零。现在
   `audiocap` 以自己的名义申请，从哪个终端、录音台、后台起都一样。代价是它重新编译过（源码改了）之后
   系统当它是新程序，会再问一次——`rex check sys` 和开录时会把这事说出来；接口没授权时录电脑声音自动
   退回 BlackHole 那条路，不会开不了录。开关记在 `~/.config/rex/system-audio`（内容是 `tap`）；想退回老路，
   删掉这个文件，或者临时 `REX_SYS=blackhole rex both`

   这个接口有个脾气：**电脑里没有任何程序在放声音时，它一帧都不给**（不是录到静音，是什么都没有）。
   开录时对方还没说话，录音就起不来。所以录的时候 `audiocap` 会自己往**内建扬声器**写静音——听不见、
   不碰 AirPods——让接口一直转。`rex check sys` 的第三步就是验证这个：什么都不放录 2 秒，必须持续出数据

**也别忘了录自己：**打电话要按「我 + 对方」（命令行是 `rex both`）。「只录电脑声音」（`rex sys`）
从来不录麦克风。

**为什么需要这个命令：**macOS 在麦克风权限被拒、或者音频链路出问题的时候，
是**喂数字静音而不是报错**。ffmpeg 一切正常、文件照常生成、零提示，
等你录完一小时才发现是空的。所以 `rex stop` 一定报峰值：

- 峰值 **−91 dB** = 精确的数字静音，什么都没收到
- 安静房间里的麦克风大概 **−40 dB** 上下，这是正常的
- 峰值 **> −0.5 dB** 会提示可能削顶

### 合着盖录，自己那一路是空的

笔记本合盖时，内建麦克风在**硬件上**断开（苹果的隐私设计）。系统照样列出
「MacBook Air Microphone」，读出来却全是 0，和链路断了一模一样。
用内建麦克风开录时 `rex` 会先查一下，合着盖就当场提示；真要合盖用，`--device`
换一个麦克风（耳机、iPhone）。

### 「几乎是数字静音」

两种原因：

1. **权限**：系统设置 → 隐私与安全性 → 麦克风 → 「rex 录音采集」要开着（第一次开录或 `rex check`
   会弹框问；拒绝过就得来这里手动开）。从 BlackHole 抓声音在系统看来也算「用麦克风」，同样要给。
2. **音频链路坏了**，蓝牙设备掉线之后常见。真踩过一次：耳机掉线后内建麦克风
   持续输出 −91 dB，直接调 ffmpeg 也一样。重启音频服务：

   ```bash
   sudo killall coreaudiod
   ```

### `rex phone` 说「一条录音都没有」，但「语音备忘录」App 里明明有

**是权限，不是没文件。**

Voice Memos 的容器 `~/Library/Group Containers/group.com.apple.VoiceMemos.shared/`
受 macOS TCC 保护，而**授权是按 App 给的**。访达能看见、语音备忘录 App 能看见，
都不代表你的终端能看见——没授权时那个目录在终端眼里就是空的。

修法：

1. 系统设置 → 隐私与安全性 → **完整磁盘访问权限**
2. 把你用的终端 App 加进去（Terminal / iTerm / VS Code…）
3. **完全退出终端再打开**——改完权限不重启进程不生效

`rex phone` 现在会把这三种情况分开报，不再混成一句「没有录音」：

| 探测结果 | 含义 |
|---|---|
| `NODIR` | iCloud 同步没开 |
| `DENIED` | 权限问题，按上面三步走 |
| `OK 0` | 目录真的是空的 |

### 「建不出直通设备」

你当前的输出设备本身就是个聚合设备。去菜单栏切回普通的耳机或喇叭再录。

### 「已经在录了」

```bash
rex status
```

看是不是真的在录。如果进程已经没了但状态文件还在，跑一次 `rex stop` 清掉。

### 上次崩了，输出设备没切回来

菜单栏手动选回去。下次 `rex` 启动时会自动清理残留的临时设备。

## 十二、给以后改这个脚本的人

**变量后面紧跟中文，必须写 `${var}` 不能写 `$var`。**macOS 只有 bash 3.2，
它判断变量名结尾用 `isalnum()`，而 `isalnum()` 认 locale——UTF-8 下会把
「）」「」」的字节吞进变量名：

```
LANG=en_US.UTF-8  →  bash: x<0xef>: unbound variable
LC_CTYPE=C        →  （hi）      ← 同一句代码
```

这条真踩过，六处，`rex sys` 一跑就退出。扫全文：

```bash
grep -nP '\$(?!\{)[A-Za-z_]\w*[^\x00-\x7F]' tools/rex.sh
```

（`-P` 要 ugrep 或 GNU grep，系统自带的 `/usr/bin/grep` 没有。等价写法：
`perl -ne 'print \"$.:$_\" if /\$(?!\{)[A-Za-z_]\w*[^\x00-\x7F]/' tools/rex.sh`）

**而且改完要在 UTF-8 locale 下跑一遍**，别只在自己的 shell 里测：

```bash
LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 rex devices
```

其余设计取舍写在 `tools/rex.sh` 的文件头注释和各个脚本的注释里，每一处都讲了为什么这么做。
